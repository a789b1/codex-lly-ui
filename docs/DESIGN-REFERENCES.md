# 设计路线纠偏 · 2026-10-24

本轮读取 DSH 插件及其 Oil UI 0.24.2 原始技能，并实际打开作品页面观察。以下是参考作品，不是本项目或 Codex LLY UI 的生成案例；不复制作品源码或重新署名截图。

| 实际查看的作品 | 值得保留的方法 | 对当前项目的具体约束 |
| --- | --- | --- |
| [Sonar Desk](https://ui.oiloil.org/works/sonar-desk/live/index.html) | 频道、聊天、成员分区明确；真实消息与操作占首屏，状态色承担任务意义 | 序间是工作台，项目和任务应直接可见，不能为了“高级”放大口号区域 |
| [ARCHON](https://ui.oiloil.org/works/archon-bust/live/index.html) | 内核结构图与产品原理一致，标题、安装入口、技术标记共用严谨的视觉语法 | 主视觉应解释产品，而不是泛用渐变和无意义装饰；营销页方法不能套进工作台 |
| [Atelier Volders](https://ui.oiloil.org/works/volders-wedge/live/index.html) | 从凳子底部的工艺细节决定镜头和标题；图像承担大部分信息，控件安静 | 先确定真实产品素材与视觉主角，再排版；不能用“深色+衬线”来冒充完整方向 |
| [Vesper Ledger](https://ui.oiloil.org/works/vesper-ledger/live/index.html)（前轮已实际操作） | 财务表格、筛选和详情共同支持判断；不是仅漂亮的静态卡片 | 视觉取舍要服务用户决策，交互证据不能代替审美判断 |

## 0.5.0 的问题

自创的短设计规范丢失了上游对标杆、素材、动效、字体与方向差异的具体指导。序间改版改变了原本已经明确的产品布局，放大展示区，还把自动检查通过用作成果重点。这不满足“保留成熟设计方法、适配 Codex”的要求。

## 0.6.0 的处理

采用上游完整技能及 14 个参考分册，保留兼容的五个脚本和比较页模板，固定来源提交并附 MIT 许可。只修改 Codex 入口、去掉自动更新及付费推广、交代真实工具边界。保留已有 MCP 验收能力作为辅助，不用它替代设计流程。

本轮不再次改动序间布局。README 仅展示 Codex 实际生成的历史页面，并明确版本。适配工具在原版序间上实际完成截图；可交互比较页用真实历史页面验证。它们证明适配可运行，不证明新版方法的视觉产出已经更好。
