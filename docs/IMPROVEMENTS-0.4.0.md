# 序间实践带来的改进

日期：2026-10-24。依据：demo/workbench/ACCEPTANCE.md 和实际工具实现。

| 实践暴露的问题 | 本次修改 | 验证 |
| --- | --- | --- |
| 方向只记录布局配色，缺少选择依据 | 方向支持任务收益、代价、手机重排，brief 支持项目质量标准；新增设计复核协议 | 保持旧参数兼容；主代理仍须实际查看画面，不自动生成审美分数 |
| 保存/刷新/焦点验收要另写脚本 | capture 增加 reload、Shift+Tab、六类显式断言 | 序间桌面和手机创建→刷新→搜索→精确标题通过 |
| 点击完成容易被误读为业务成功 | 无断言 review；失败停止且保存现场 | 真实浏览器故意错误预期，保存失败截图，后续步骤未执行 |
| axe incomplete 只有数量，pass 容易误导 | review 状态，保留目标选择器和节点 HTML | 序间三尺寸均正确标记 review；装饰背景对比度需人工判断 |
| 报告只有自动审计，真实交互证据散落 | interactions 合并 capture.json 和截图，纳入哈希清单 | 完成版 report.html 同时展示审计和桌面/手机流程 |

第一次复跑把项目名称前一个控件误认为“保存”。断言发现实际是关闭按钮，失败现场保留在 evidence/plugin-0.4.0/desktop；按实际焦点顺序修正脚本，再验证关闭按钮→反向 Tab→保存。没有修改页面来迎合错误预期。

完成版证据：demo/workbench/evidence/plugin-0.4.0-final/report.html。
测试：14 项通过，包括真实 Chrome；构建、类型检查、插件打包校验通过。

剩余边界：设计规则需要执行者落实，不能保证每次生成都好看；报告不自动认证人工判断；故障注入、后端业务语义及跨会话登录仍使用宿主浏览器补测。本次未重新声称全面 WCAG 认证。
