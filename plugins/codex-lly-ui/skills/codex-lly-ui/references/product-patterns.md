# 按任务选择界面组织方式

这些是判断问题，不是预设配色与页面模板。

| 使用情境 | 先确认 | 结构建议 | 常见代价 |
| --- | --- | --- | --- |
| 少量长期项目的创作工作室 | 今天推进哪一份、等谁反馈 | 最近交付重点 + 带缩略图的项目记录 | 重点区域过大时挤压项目检索 |
| 大量订单、费用或库存 | 哪些异常必须处理、怎么缩小范围 | 可见筛选 + 可比较的行 + 详情 | 高密度需要明确字段和键盘支持 |
| 编辑、写作、研究 | 当前内容及其上下文 | 内容占主要空间，工具按任务分组 | 过度隐藏工具会降低发现性 |
| 服务预约、首次购买 | 是否适合我、下一步怎么做 | 决策信息按顺序出现，再进入操作 | 过量展示会延迟行动 |
| 收藏、素材选择 | 依靠外观还是属性辨认 | 外观重要用图；精确属性重要用列表 | 网格不适合比较很多字段 |

## 序间案例中的可迁移经验
最早版本：固定侧栏、三张统计、等大的四张项目封面、右侧日程、重复鼓励文案。
问题：信息都在，但最近交付与下一步操作没有形成视觉重点。
改版：横向导航释放宽度；最近交付由真实状态排序；一张交付稿形成身份；其他项目使用紧凑记录。
字体以宋体标题建立创作语气，正文保持易读；灰紫承载品牌、深墨绿承载操作、朱红提示截止。
代价：突出一项交付会减少同屏项目数量，需要通过紧凑行和搜索补偿；大规模团队不宜照搬。
这是案例推理，不能把灰紫、宋体或稿纸造型复制到每个任务。
