# 验收协议

把证据分为三类：自动检测、真实交互观察、人工视觉判断。任何一类都不能代替另外两类。

## 自动检测

审计至少覆盖目标桌面和手机尺寸，必要时加平板。检查 axe violations 与 incomplete；critical/serious、意外横向溢出、断图、运行时错误和资源超时会导致 gate=fail。中低严重度结果也需阅读，不能因为 gate=pass 就忽略。

审计默认开启 reduced-motion 以稳定截图。动画与滚动体验要另外观察，不能从审计静态图推断通过。

## 交互观察

从真实入口走完整主路径。检查结果是否真实出现，而不只看点击事件能否派发。

- 表单：标签、必填、错误、错误后输入保留、提交结果。
- 保存：保存后重新读取，刷新后检查；未连接后端时如实说明。
- 键盘：Tab 顺序、可见焦点、Enter/Space 激活、Escape 关闭及焦点返回。
- 反馈：加载、空、错误、成功、禁用和重复操作。

`lly_ui_capture` 的正文与焦点记录用于核对结果，不自动推断“业务正确”。需要选择器时从实际 DOM 获取，避免猜测。

## 视觉判断

在真实阅读尺寸查看截图，检查主次、内容密度、字重、换行、控件状态和相邻元素。长页面要看整体节奏；局部放大用于定位问题，不用于掩盖正常尺寸下的不足。

## 基线与差异

capture 保存基线时应使用用户认可的版本。compare 先核验基线哈希，再比较相同视口。缺失视口、尺寸变化或超出容忍比会失败。

像素变化说明“变了多少”，不说明“变得更好”。动态时钟、随机图片和不同数据会产生噪声，应先准备稳定数据。基线替换必须有任务授权，不能为通过检查而覆盖。

## 报告

只使用真实 audit.json 和对应截图。报告展示自动结果、实际画面与观察到的变量，附 SHA-256 文件清单。哈希用于发现文件改变，不是第三方认证或电子签名。

交付中说明没有做的检查。不要把编写好的测试脚本称为已执行，也不要把自动无障碍检查称为全面 WCAG 合规认证。
