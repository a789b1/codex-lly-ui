# 从工作内容推导设计

先做设计判断，再选组件。不是每个项目都需要大标题、侧栏、统计卡片或品牌主视觉。

## 1. 内容排序
写下用户进入页面后的三个真实问题，按“决定下一步的价值”排序。
对每块内容标注用途：做决定、执行操作、定位对象、解释状态、建立身份。
找不到用途的块先删掉。统计数字只有在影响下一步时才占首屏主位。
有现成数据时让它决定排序，不用硬编码的“本周重点”假装智能。

## 2. 选择一个视觉重点
从项目自身挑一个对象：创作者的交付稿、物流的包裹位置、编辑的稿件状态。
说明为什么这个对象值得占空间，以及它连接哪一个可执行操作。
其他区域用更安静的尺寸、颜色和密度。不要把每个区块都做成主视觉。
如果主视觉不能帮助识别对象或理解状态，回退到内容布局，不添加装饰填空。

## 3. 用结构表达工作方式
先画两个简短结构草图，检验内容关系而不是换颜色：
- 先决策后查找：当前需要处理的对象 → 全部记录 → 辅助事项。
- 先检索后操作：过滤/搜索 → 高密度结果 → 选中对象详情。
根据对象数量、频率和用户目标选择。四个项目与四百个项目不能使用同一展示密度。
对手机单独排序；不能只是把三列机械堆成很长的一列。
保留现有有效习惯，重排不应破坏入口、状态和已保存数据。

## 4. 字体与色彩承担角色
分别定义品牌/标题、正文/控件、数字/日期三类角色。字体可以共用，但理由必须明确。
中文标题检查实际字形和换行；衬线不等于高级，大字号不等于有层级。
色彩分为底色、阅读色、交互色、状态色；装饰色不能抢过风险或截止日期。
对照片、图形和代码绘制分别说明用途。产品工具页不需要为了显得丰富强塞图片。

## 5. 做代表片段再扩展
先实现一个完整任务片段：对象 + 状态 + 操作 + 结果。
在桌面和手机原尺寸看过后再扩展，修正字体比例、密度和首屏优先级。
先形成一套可复用变量和组件规则，再批量生成剩余内容。

## 6. 自我反驳
提交前问自己：
- 换成另一个行业，这个画面是否几乎不用改？如果是，重新检查对象与结构。
- 是否只换了配色，主要内容关系完全没变？
- 所谓“更有设计感”是否牺牲了信息可见性或操作便利？
- 哪三项变化用户能在真实画面中直接看到？每项给出旧版问题、新版处理和仍有的代价。

不要把一次更漂亮的样例当作插件普遍提升的证明。保存前后实图和适用边界。
