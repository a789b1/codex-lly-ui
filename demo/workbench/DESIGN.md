# 序间：从插件到实际产品

## 目标

独立设计师需要在同一页看清多个客户项目的状态、近期交付与今天的行动，并能快速建立新项目。

## 方向比较与选择

插件 `lly_ui_brief` 保存了三种结构；`lly_ui_explorer` 在真实浏览器中渲染了三份候选。

- A 轻盈工作台：侧导航 + 作品封面卡片 + 交付与待办侧栏。
- B 交付日历：以一周日期为中心，突出到期先后。
- C 项目索引：以密集表格为中心，突出项目横向比较。

选择 A：独立创作者通过品牌封面快速识别项目，同时看见交付与行动。B 在并行创作时分散项目上下文，C 更适合大量记录的管理场景。

## 视觉系统

冷白 #F4F6FA、墨蓝 #202B44、群青 #3658D4、浅蓝 #E9EEFF；浅绿与陶橙只出现在作品封面。系统中文无衬线承载操作，衬线仅用于咖啡品牌的自制封面字样，等宽字体用于辅助数字。功能正文最小 12px，主要标题 25–29px。

封面均由项目代码绘制，不使用外部素材、字体或虚构客户成果。页面里的品牌、用户和项目是本次演示的虚构内容。

## 实现范围

- 本地浏览器保存项目与待办；刷新恢复。
- 项目搜索、状态筛选、空结果与清除筛选。
- 新建项目对话框、必填与日期校验、保存失败恢复。
- 项目详情与 进行中 → 待反馈 → 已完成 的推进。
- 待办勾选、进度与交付日程联动。
- 原生 dialog 提供焦点约束，Escape 关闭，关闭后焦点返回触发控件。
- 卡片悬浮、弹窗入场、待办进度与日程定位反馈；reduced-motion 下关闭动画。

不含账号、后端、多设备同步、邮件发送或真实客户协作。动作使用“移至待反馈”，仅改变项目状态，不暗示已发送客户消息。

## 验证方式

使用已安装的 Codex LLY UI 插件实际调用，而非只运行工具的单元测试。插件生成三方向比较、真实交互证据、多视口审计及验收报告；Ego 浏览器补充刷新持久性、键盘和保存失败测试。最终结论写入 ACCEPTANCE.md。
